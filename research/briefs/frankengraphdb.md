## frankengraphdb (untagged, default branch) (@ cfac16678c6a)

**What it actually is.** A five-week-old (inception 2026-07-15 per CHANGELOG.md:5-7), agent-written Rust workspace of 20 crates (~338K lines) that is mostly *verification constitution* plus a thin storage spine: a hash-chained, content-addressed commit log with a two-fsync protocol (`fgdb-chronicle`), a tier-D delta-block adjacency store with half-open MVCC intervals (`fgdb-strata`), a reference oracle + differential/lab-runtime test harness (`fgdb-reference`, `fgdb-sim`), a claim-class lattice and evidence-envelope type system (`fgdb-claim`, `fgdb-evidence`), identity-bound wrappers over asupersync's sequential statistics (`fgdb-calibrate`), and a 60K-line TOML claim-registry checker (`tools/registry-check`). The public engine API is `Database::create/open/write` plus `neighbours/neighbours_at/edges/vertices` and a GQL parser that accepts exactly one edge pattern (optionally two-hop) (crates/fgdb-gql/src/lib.rs:1-10). Tested heavily by `#[test]` counts (2,200+ across crates, 312 in fgdb-sim) and integration suites; I could NOT build or run tests here (pinned `nightly-2026-07-05` not installed; asupersync/franken_networkx git deps not cached), so "tests pass" is unverified.

### M1. Claim-class lattice as a sealed type system + `justified_by` edge rule
- Mechanism: closed ranks `invariant(5) > proof(4) > bounded_model(3) > statistical(2) > slo(1) > benchmark(0)`; `try_justify(self,target)` succeeds iff `rank(evidence) >= rank(target)`, returning a non-forgeable `Justification` or typed `LatticeViolation` (fgdb-claim/src/lib.rs:70-96). Type-level twin: sealed marker structs and a sealed `AtLeastAsStrongAs<T>` relation implemented only for the 21 legal pairs, so `justify::<Statistical, Proof>()` is a compile error (lib.rs:153-226, 364-372). `EvidenceClaim::max_registry_class` caps what an evidence *kind* may justify: formal model `ModelOnly` -> bounded_model, `RefinedToImplementation` -> proof, statistical/config-model -> statistical, empirical gate -> benchmark (lib.rs:484-548). Registry side: every `justified_by` edge in invariants.toml is checked, `class_escalation` on rank(justifier) < rank(clause) (tools/registry-check/src/validate.rs:222-252; constitution.toml `[lattice]`).
- Candidate home: **calibration layer + claims DB** (and the foundations auditor's core check: a PROVEN claim cannot carry a `justified_by` edge to a STRONG-EMPIRICAL/CONJECTURE premise).
- Cost: trivial (1,356 lines, std-only); re-implement as a rank table + edge check in whatever Cairn uses; type-level enforcement only if Cairn is in Rust/typed.
- Evidence: **PROVEN-in-source** — impl read; unit tests sweep all 36 pairs (lib.rs:581-640); integration test proves type-level transitivity at all 56 triples by compilation (tests/claim_lattice_laws.rs:1-70); 15 compile_fail doctests.
- Epistemics risk: none; it is the mechanical form of "weaker evidence may inform but never justify stronger". Keep the lattice data immutable (Cairn's rule) — the repo makes it sealed for exactly that reason.

### M2. Evidence envelope: claim + content-addressed evidence + declared context + mandatory fallback; 4-grade replay completeness that only weakens
- Mechanism: `EvidenceEnvelope{claim, evidence_oid, selection_policy_oid, strata_identity, propensity_support_identity, calibration_window, regime_epoch, fallback}` with private fields, constructible only via `new` (fallback is a required arg; compile_fail doctests at fgdb-evidence/src/lib.rs:1044-1150); never edited, only superseded; `to_canonical_binding_bytes` is a length-delimited, tagged transcript and `binding_address_with(hash)` hashes it (lib.rs:1212-1245); `justify(target)` applies M1 at the envelope boundary (lib.rs:1299-1301). `ReplayCompleteness ∈ {Replayable, StructuralReplay, VerifiableIfArtifactsSupplied, AuditOnly}`; `weaken_for_redaction` can only move down to AuditOnly (lib.rs:459-520, 647-668).
- Candidate home: **claims DB (calibration tag + evidence pointer)** and **reproducibility gate** (the completeness grade is a finer "substrate node present / partially / absent").
- Cost: small; one struct + canonical encoder.
- Evidence: **PROVEN-in-source** — tests/evidence_relations.rs:1-40 records six mutation-proven relations (each mutation applied, observed RED, reverted).
- Epistemics risk: low; Cairn must map only `Replayable`/`StructuralReplay` to "admissible" — `AuditOnly` must stay inadmissible.

### M3. Proof-lane gate: "checked" = prover actually ran, under a pinned toolchain, and the prover's own output was scanned for admits
- Mechanism: (a) source scan masks comments/strings, whole-token matches `sorry|admit|axiom|native_decide`, requires `theorem|lemma|example` (liveness.rs:1116-1200; self_test controls at 1746, 1940-2047); (b) runner refuses if `lean` missing ("Refusing to report green on an unrun prover", g0_proof_lanes_e2e.sh:121), checks `lean --version` equals `formal/lean/lean-toolchain` pin (:151), then — because Lean exits 0 on `sorry` — greps prover stderr for `declaration uses .sorry.` with a matcher self-test for both quoting spellings (:53, :98, :171); (c) zero checked lanes is FAIL (:224); (d) a `declared` lane may be cited only by a `stub` clause (proof_lanes.toml:1-80).
- Candidate home: **gate layer: formalization gate**.
- Cost: a shell script + ~100 lines of scanner; requires pinning elan/lean.
- Evidence: **STRONG-EMPIRICAL** — implementation and its self-tests read; I could not run lean (not installed here).
- Epistemics risk: none; strengthens "green Lean" into "green Lean, no admits, pinned prover". The `axiom` flag is deliberately loud (false positives on legitimate axioms) — keep it loud.

### M4. Hash-chained commit markers with branch-head compare-and-swap
- Mechanism: canonical marker bytes (marker.rs:133-178); `chain_hash = BLAKE3(domain ‖ prior_chain ‖ canonical_bytes)` (:180-187); `marker_oid = chain_hash`, so identical content at different positions is a distinct history identity (:509-516); `HeadUpdate{graph, branch, expected_previous}` is a CAS — all heads in a marker are checked before any is applied (:495-507); gap-free `commit_seq`, monotone command seq; `verify` replays `validate` from origin so every append-time law is re-enforced (:412-440, 533-560). No forward references keeps the DAG acyclic by construction (:17-23).
- Candidate home: **state layer: branch tree** (tamper-evident, concurrent-agent-safe head advancement; lineage kept forever) — also usable for the dead-end ledger's REFUTED-permanence.
- Cost: ~600 lines; in SQLite: a `chain_hash` column + `expected_previous` check in the same transaction.
- Evidence: **PROVEN-in-source** — tests/commit_stream.rs:85-709 (tamper at any field breaks chain at that seq; failed CAS leaves every branch untouched; prefix verifies without suffix; forged-but-lawful chain verifies).
- Epistemics risk: none.

### M5. Snapshot provenance + fork-at-boundary read semantics (oracle)
- Mechanism: `Snapshot` carries an opaque `authority`, a stream-prefix digest keyed by sequence, and a lineage digest over the fork chain `(graph,branch,parent,fork_boundary)*`; `check_provenance` refuses a snapshot from another database or lineage as `ForeignSnapshot` (reference lib.rs:2683-2712, 2821-2850, 2857-2900). `fork_branch_at` materializes the parent's *history folded to the boundary*, not its present; reads cap each ancestor at min(high, fork boundaries) so a child's pre-fork read equals the parent's without post-fork leakage (:3080-3125, :2940-2975).
- Candidate home: **state layer: branch tree** (what "child inherits parent at fork" must mean) and **skill self-tests** (oracle-differential pattern, generated_histories.rs:1-40).
- Cost: moderate; the oracle is O(n) by design. Evidence: **PROVEN-in-source** (tests/snapshot_provenance.rs, tests/branch_fork.rs). Epistemics: none.

### M6. Identity-bound sequential tests (SPRT fixed-point, e-process/conformal wrappers)
- Mechanism: SPRT over binary outcomes in u128 fixed point with an *interval* likelihood ratio (lower rounded down, upper rounded up), contiguous-sequence enforcement, terminal-state refusal (sprt.rs:234-300, 625-700). E-process: `core` is `asupersync::lab::oracle::eprocess::EProcess` (eprocess.rs:13); wrapper binds an immutable `TrialIdentity{monitor, filtration, window, regime_epoch, candidate, pinned_fallback}`, canonical float bits in evidence, and a two-outcome gate `PromoteCandidateAgainstPinnedFallback | RetainPinnedFallback` (:662-760). Registry law: statistical rows may never justify invariant/proof (evidence.toml:1-20).
- Candidate home: **calibration layer (small-numbers gate)** — as a pre-registered, anytime-valid promotion protocol with a pinned conservative default.
- Cost: e-process math lives in asupersync (heavy git dep); SPRT is local and tiny. Evidence: **CONJECTURE** for Cairn's use — wrappers read and unit-tested (4/12/17 tests), core math not verified here. Epistemics: acceptable only if promotions cap at STRONG-EMPIRICAL.

### M7. Gate-honesty protocol: negative controls, metamorphic "what if the checker were broken", negative-evidence ledger
- Mechanism: clause promotion to `live` requires checker AND a distinct negative test that can itself fail (invariants.toml:47-90); metamorphic relations over the checker (tests/metamorphic.rs:1-50); NEGATIVE_EVIDENCE.md entries `doctrine/bead/repair/claimed/actual/caught_by/signature` keyed to "a gate reported a verdict it had not earned" (docs/NEGATIVE_EVIDENCE.md:55-110); claims-lint requires every load-bearing marker to resolve to a registry row (claims_lint.toml:1-60).
- Candidate home: **gate layer (no-go checklist / skill self-tests)** and **negative-results map** (format only).
- Cost: the repo's checker is 60K lines — do not adopt; the *rule* costs one extra test per gate. Evidence: **STRONG-EMPIRICAL** (files read; checker not run). Epistemics: strengthens.

### Storage/query for Cairn's scale — nothing accretive
Reads are whole-history validate + linear filter (root.rs:894-915); no index, no transitive reachability (only oracle `paths()` with required `max_hops`, reference lib.rs:848-880); MVCC is the standard `[created_at, retired_at)` interval (strata lib.rs:271-290). SQLite with an edges table + recursive CTE beats this today for "all claims transitively depending on X".

**Verdict.** Borrow M1 (lattice + `justified_by` rank rule + evidence-kind cap) and M3 (prover-output admit scan, toolchain pin, zero-checked = fail) as re-implemented mechanisms; M2/M4/M5 are good shapes for the claims DB and branch tree. Do not depend on the crates.
