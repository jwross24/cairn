# Idea (a): small-image-primes cascade ordered by kill power per cost

Code: src/lane2.c, switch `LANE2_A` (bit 1 = reorder + shared-cofactor chain, bit 2 = bitmap pre-test on the small primes). No other file.

Spec (re-implementable blind). The child test is a conjunction of characters; every necessary condition may be tested in any order without changing the output.
1. Bit 2: for each prime p <= 255 with a single-prime image set K_p (here 73 and 137), build once per parent a p-bit bitmap of T_p * K_p
   (T_p = 2^a 3^b 7^c mod p of the parent, K_p = subgroup generated by 3^{u0} 7^{u1} over the rows of Uold). A candidate whose residue is outside the bitmap is dead
   (counted as dead only after the "residue = 0 mod some p" check, so the counters stay equal).
2. Bit 1: for the large prime p3 let R be the set of prime-power factors q^e of p3-1 whose component has image smaller than its group (here 16, 9, 625);
   M = prod R (90000), D = (p3-1)/M (1111). Per candidate compute z = y^D (one 11-bit exponentiation, 4 candidates interleaved), then the l-part element
   z^(M/q^e) (5-part: z^144). Test components in decreasing kill/cost order (5-part, then the others), table lookup for the discrete log in the order-q^e subgroup.
3. Anything that survives goes through the unchanged full test (process_rest) so the emitted OPEN/EXACT lines are those of lvlN.
Planted mutant AMUT (LANE2_AMUT=4): use exponent M/q^e - 1 in the 5-part element.
Results: RESULT.md (identical on 228/228; stand-alone x1.08 total, x1.06 on the 12 heaviest; with E0 x1.43).
