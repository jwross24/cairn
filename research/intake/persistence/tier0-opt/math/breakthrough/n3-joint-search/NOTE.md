# N3: a joint archimedean and 10-adic search for Tier C

Lane N3, 2026-10-21 (night). Code and raw outputs sit beside this file. Nothing under `tier0/` or any pre-existing file
was touched. Labels: PROVEN-ON-PAPER (argument written here, not Lean-checked), STRONG-EMPIRICAL (measured), HEURISTIC
(a model, stated), CONJECTURE. No step rests on an unproven conjecture. Nothing is Lean-checked, so nothing here is PROVEN.

## 0. Verdict

1. The decision procedure for one (head word, tail word) pair is exact, sound and complete: PROVEN-ON-PAPER (section 1),
   exercised on planted S-units with exponents up to 10^281 (n about 10^281 digits), every one recovered, every perturbation refused.
2. The pinned-digit budget is `P + K - 0.301 a >= 2 log10 G' + 0.4`, not `3 log10 G'`. The tail fixes `a` (it is read off as
   `v2` of the tail) and `n` is determined by `(b, c)`, so the box has two free dimensions, not three. The archimedean-only
   search (a free) needs `3 log10 G'`; the joint search saves about 10^5.6 to 10^7.9 over it at the six Tier-C vertices.
3. The number of pairs is the number of ways to place the k non-1 digits among the `w = P + K` pinned positions,
   `C(w, k) * W(M)`, and it does not depend on how `w` is split between head and tail (Vandermonde). At the six Tier-C vertices
   this is 10^58.7 to 10^79.6 for the top equation of each vertex (section 3). No pruning exists below `w`.
4. Compared with the current pipeline (anchored open@96 patterns times sandwich sub-cosets) the joint search is the same
   computation in a different coordinate system: once the level-96 sieve feeds it, the case count is within 10^2 to 10^3 of the
   sandwich's `(D+1)^k`, at 10^37 to 10^56. It does not make Tier C feasible.
5. The count is feasible (10^22, the size of the level-12 enumeration) only for `log10 G' <= 25`. A length bound that small
   already sits below the 10^27 digits the level-96 lattice forces on every non-anchor candidate, so the sandwich closes
   the pattern without any search. The regime where the joint search is cheap is the regime where it is redundant.

## 1. The decision procedure for one pair

Notation. A solution is `y' = 2^a 3^b 7^c` with `n` decimal digits. `D` is the integer formed by its top `P` digits (any
words, 1s included), `Bt` the integer formed by its lowest `K` digits (leading zeros allowed), `n >= P + K`. Natural logs
`l2, l3, l7, l10`. `Q` is a bit precision and `L_i = floor(2^Q ln i)`.

Input: `D, P, Bt, K, nmin, nmax`. Output: a list that contains every `(a, b, c, n)` with `nmin <= n <= nmax` and `y'`
having top digits `D` and `y' = Bt (mod 10^K)`.

Steps (code: `joint.py`, `query`, `query_fixed_a`, `tail_lattice`, `enum_ball`).

1. If `5 | Bt` return nothing (`5 does not divide y'`). If `2^K` does not divide `Bt`, then `a = v2(Bt) < K`: `v2(y') = a`
   and `y' = Bt (mod 2^K)` give `v2(Bt) = a` whenever `a < K`, and `a >= K` would force `2^K | Bt`. If `2^K | Bt` then `a >= K`,
   and `a` runs over `K .. floor(nmax log2 10) + 2` (the bound is `2^a < y' < 10^nmax`); each value is one pass of steps 2 to 6.
2. Tail congruences (PROVEN-ON-PAPER). With `a < K`, `y' = Bt (mod 10^K)` is equivalent to `3^b 7^c = Bt 2^-a (mod 5^K)` and
   `3^b 7^c = Bt / 2^a (mod 2^(K-a))`. With `a >= K` only the first holds. The first is a linear congruence in `(b, c)`:
   2 is a primitive root modulo `5^K` (primitive modulo 5, and `2^4 != 1 mod 25`), so with `lambda_x = dlog_2(x)` the condition
   is `b lambda_3 + c lambda_7 = lambda_t (mod 4*5^(K-1))`. The second: each odd residue modulo `2^m` (`m >= 3`) is uniquely
   `(-1)^e 5^x`, `e` in `{0, 1}`, `x` modulo `2^(m-2)`, giving one congruence modulo 2 and one modulo `2^(m-2)`; `m = 2`
   gives the modulo-2 one only; `m <= 1` gives none. The solution set of the system is an affine lattice `p + Lambda` in
   `Z^2`, built by intersecting the congruences one at a time (`solve_system`: the kernel of one congruence in two unknowns
   is generated by `(r2', -r1')` and `(u m', v m')` from the extended gcd, and has the right index, so the two generate it).
   Measured determinant: `|det Lambda| = 5^(K-1) 2^(K-a)` for `a < K` (9 settings, K up to 200, exact to 0.01 in log10),
   so the tail pins `K - 0.301 a` digits, not `K`.
3. Head slab (PROVEN-ON-PAPER). `y'` has `n` digits and top digits `D`, so `D 10^(n-P) <= y' < (D+1) 10^(n-P)`, which is
   `ln D - P l10 <= a l2 + b l3 + c l7 - n l10 < ln(D+1) - P l10`. Write `F = b l3 + c l7 - n l10`.
4. Box. `y' < 10^nmax` gives `b <= (nmax l10 - a l2)/l3` and `c <= (nmax l10 - a l2)/l7`. Integer bounds `bmax, cmax` use `L_i`
   with margin +2 (`nmax / L3 < 1`, so replacing `ln 10` by `(L10+1)/2^Q` costs less than the margin).
5. Fixed-point enclosure (PROVEN-ON-PAPER). Replace `F` by the integer `F_int = b L3 + c L7 - n L10` and the window ends by
   `floor(2^Q ln D) - P L10 - a L2` and the same with `D+1`. Each `L_i` is within 1 of `2^Q ln i`, so
   `|2^Q F - F_int| <= b + c + n` and each window end is within `P + a + 1`. Widening the window by
   `err = bmax + cmax + nmax + P + a + 4` on both sides therefore contains every true solution. A wider window costs only
   more enumerated points, never a missed one. The logarithm floors are computed by `mpmath` at `Q + 128` bits; a floor
   is wrong only if `2^Q ln i` lies within `2^-128` of an integer (assumption A1; `mpmath.iv` would certify it).
6. Enumeration (PROVEN-ON-PAPER). Parametrize `(b, c) = p + s u1 + t u2` (Gauss-reduced, `p` moved near the box center), unknowns
   `(s, t, n)`. Scale the three coordinates `2b - bmax`, `2c - cmax`, `F_int - Fc` so the box-slab is the cube `|X_i| <= Omega`
   with `Omega = bmax cmax HW` (`HW` the half window; `[LO, HI]` lies inside `Fc +- HW` for `Fc = floor((LO+HI)/2)`,
   `HW = ceil((HI-LO)/2)`). Every cube point lies in the ball of radius `sqrt(3) Omega`. The three-column integer basis is
   LLL-reduced in exact rationals and all lattice points of the ball are listed by Fincke-Pohst on the exact Gram-Schmidt data
   (the square-root bounds are rounded outward). Each point is tested against the exact box, window and `nmin <= n <= nmax`.
7. Verification (filter only). A survivor must satisfy `2^a 3^b 7^c = Bt mod 10^K` (exact `pow`) and have `n` digits with
   leading digits `D` (`mpmath`, precision `0.31 * bits(exponents) + P + 60` decimal digits; a leading-digit string within
   1e-20 of a boundary is kept). Step 7 can only remove a candidate; the claim "no solution" rests on steps 1 to 6, which use
   integer and rational arithmetic only, plus assumption A1.

Theorem 1 (PROVEN-ON-PAPER given A1). `query` returns every `(a, b, c, n)` described above. Proof: steps 1 to 6 are
necessary conditions that each true solution satisfies and the enumeration lists every integer point satisfying them.

Theorem 2 (coverage). Fix a vertex `s` and a multiset `M` with product `s`. Let `H` be the set of words of length `P` over
`{1} + digits(M)` and `T` the same for length `K`, restricted to pairs whose non-1 digits form a sub-multiset of `M`.
Every child `y'` of the equation `M` with `n >= P + K` has top-`P` and bottom-`K` words in `H x T`, so querying every pair
and keeping the survivors whose digit multiset is exactly `M` returns every such child with `n <= nmax`. The remaining
children have `n < P + K` and are found by listing all `2^a 3^b 7^c < 10^(P+K-1)`. Digits in the middle (pairs that use fewer
than `k` digits) need no separate treatment: the head slab and tail congruences hold whatever lies between the windows.

Expected number of enumerated points for one pair (HEURISTIC: equidistribution of `log10 y' mod 1`, the same model B1 uses):

    E  =  bmax * cmax * log10(1 + 1/D) / (5^(K-1) 2^(K-a)),     bmax cmax = 2.48 nmax^2.

`E <= 1` needs `P + K - 0.301 a >= 2 log10 nmax + 0.4`. With `a` free (head only) the count is `bmax cmax amax` over the head width,
which needs `3 log10 nmax`. The decision itself never depends on the model: a point is found if it exists.

Cost per pair, Python with exact rationals, one core, `nice -n 10` (`t_planted_out_final.txt`): 9 ms at 10^12, 56 to 91 ms at
10^40, 0.21 to 0.45 s at 10^70, 0.39 to 0.64 s at 10^100, 1.4 to 1.5 s at 10^150, 3.9 to 5.0 s at 10^220, 6.8 to 8.1 s at 10^281 (w about 580). The
claim "milliseconds" is not met by this code; a C lattice library would shorten it, not measured.

## 2. Organizing prefixes and suffixes

2.1 Split invariance (PROVEN-ON-PAPER, `count2.py` asserts the identity). The pairs with `J` digits in the head window and
`L = k - J` in the tail window number `sum_J C(P, J) C(K, k-J) = C(P + K, k)` for every split, times the arrangement count
`W(M)` of the multiset. The head/tail split is a free parameter chosen for query cost, not for pair count. A meet-in-the-middle
that joins a head list to a tail list through a hash does not exist here, because the pair test is a lattice intersection, not
an equality (the same reason `h3-h4` gives for the representation technique).

2.2 Partial-slab pruning (HEURISTIC survival model, exact decision). A head of extent `s` has a non-empty slab with
probability about `min(1, bmax cmax 10^-s)` when `a` is known and `min(1, bmax cmax amax 10^-s)` when it is free, that is
`B^2 10^-s` against `B^3 10^-s`. Head-only pruning therefore starts at `s = 3 log10 B` (B3's reduction of the top gap, and the T8
per-prefix bound of 3 to 4 `log10 B`). A tail of extent `K` is pruned by coset
emptiness only from `K - 0.301 a = 2 log10 B`. Below those extents nothing is pruned, and the unpruned layer is the whole
pair set. The measurement at toy scale (`proto_out.jsonl`) shows the only free filter: the tail congruences alone are
inconsistent for 55 to 73 percent of tails (56 percent over 43,785 queries; cause not examined, consistent with the subgroup generated by 3 and 7 modulo `2^m` having index above 1), a constant factor.

2.3 Reusing the open-pattern machinery. The level-96 sieve acts on a pair only when it is closed (all k digits placed), through
positions modulo 96 and `n` modulo 96. Lifting an open@96 residue pattern to actual positions inside a window of `w` digits
gives each digit `floor(w/96) + 1` choices (a copy in the window, or the middle), which is the sandwich's `(D+1)` with
`D = w/96`. So the joint search with the sieve costs `open@96 * (w/96 + 1)^k`, against the sandwich's `open@96 * (D+1)^k`
(`count2.py`, last two columns). The sieve's selectivity (about 10^-19.5 at k = 31: unfiltered 10^59.0 against the pipeline's
10^39.5) is what makes either feasible at all.

2.4 Rank reduction by `n mod 3` and `y mod 7` (HEURISTIC counting, also noted in B1 as L4). `y mod 3 = n + sum(d - 1)`, so
`b > 0` iff `n = -sum(d-1) mod 3`. For a closed pair `y mod 7` follows from `n mod 6`. About 4/7 of pair-and-residue classes then
have `b = c = 0` (`y' = 2^a`, an O(1) check), 38 percent leave one exponent (window `log10 B`), and about 1/21 keep both.
This divides the cost by about 10 to 20, not by an exponential factor.

## 4. Prototype and controls

Planted S-units (`t_planted.py`, `t_planted_out_final.txt`). Random `a < 120`, `b, c` of size 10^E for E = 6 .. 281 (so `n` up to
10^281 digits), head and tail words taken from the real top `P = E + 6` and bottom `K = E + 6 + a/2 + 1` digits, box
`nmax = 2n`. The query returns exactly the planted `(a, b, c, n)` in every run with `a < K - 5` (3 trials at each of
E = 12, 40, 70, 100, 150, 220, 281; a trial whose random `a` exceeds `K - 5` is the a-free branch and is tested separately).
One lattice point is enumerated per query. Planted negatives: changing the tail by `2^(a+1)`, or adding 7 to the head word,
returns the empty list in every run where the perturbed tail stays coprime to 5. The a >= K branch (`t_afree.py`) scans `a` over
`K .. K + 80` and returns only the planted vector at E = 6, 12, 24, 40 (8 of 8). `t_small.py`: the affine tail lattice agrees with
brute force on 200 random cases (`b, c < 40`, 1600 points each, 0 disagreements). A design error caught along the way is the reason
for the `K - 0.301 a` term in section 1: with `K = E + 6` and `a = 40` the tail pinned only `K - 0.301 a = 34` digits and 28 true
S-units matched head and tail.

Vertex runs against the recorded verdicts (`proto.py`, `proto2.py`, `gather.py`; vertices from `runall_final.jsonl`, whose
records list `known` children and `complete_below`). For every multiset `M` of the vertex the driver queries every pair of
`P`-digit head and `K`-digit tail words over `{1} + digits(M)` (sub-multiset condition), loops `a` over
`K .. floor(nmax log2 10)+2` for tails divisible by `2^K`, lists all `2^a 3^b 7^c < 10^(P+K-1)` for the short children, and keeps
the numbers whose non-1 digits are exactly `M`. `nmax = 30`.

## 5. Where this fails

1. Pair count (dominant). `C(w, k) W(M)` with `w = 2 log10 G' + 0.4 + 0.301 a` is 10^58.7 to 10^79.6 (top equations, six vertices),
   at 7 s per pair. Split invariance (2.1) removes the head/tail balance as a lever; the sieve (2.3) removes about 19 orders and
   lands on the sandwich's count; rank reduction (2.4) removes one more. HEURISTIC for the sieve and rank figures, exact for the pair count.
2. The window rule depends on `G'`, which is the B3 Baker bound (Matveev for the top forms, Bugeaud-Kaneko for the 5-adic
   side, with the constants of `h3-h4/REPORT.md`; Yu's original not read). The search lowers no height bound; it spends the bound.
3. The pinned budget scales with `a`: each unit of `a` removes 0.301 tail digits (measured, section 1), so `a = 160` adds 48 to `w`.
   If `a >= K` the tail gives no 2-adic information and the query needs the `a` loop (80 to 130 queries per pair at toy scale); the
   version with `a` as a third lattice coordinate and the 5-adic congruence only needs `P + 0.7 K >= 3 log10 G'`. T7 bounds `a` by the
   lowest positions but does not make `a < K` automatic.
4. Children with `n < w` fall outside the pair argument (the windows would overlap). They need a census of S-units below 10^w
   (about 2.4e8 at w = 560, 6.7e8 at w = 790); the stored census stops at 10^300 (37,375,388 S-units).
5. No pruning exists below the extents of 2.2 (HEURISTIC survival model). Prefix tests are exact but kill nothing before
   `2 log10 B` (tail known) or `3 log10 B` (head only). The B3 reduction of the top gap (10^14.7 to about 10^3) is this effect at one gap.
6. The exceptional prefixes of T8 (a sparse prefix followed by a long run of 1s) are not special here: they are pairs whose query
   returns a lattice point, and the point is tested directly. The cost grows when many pairs return points, which happens when
   `P + K - 0.301 a` falls below `2 log10 nmax` (the toy runs at P = K = 3 enumerate 0.35 to 0.6 points per query).
7. The exact LLL and Fincke-Pohst are Python with rational arithmetic. The logarithm floors use `mpmath` at `Q + 128` bits and are not
   interval-certified (assumption A1). Verification of leading digits is `mpmath` at precision above `digits(n) + P + 60`, not interval
   arithmetic; borderline strings are kept, so verification can only add candidates.
8. Nothing here is Lean-checked.
