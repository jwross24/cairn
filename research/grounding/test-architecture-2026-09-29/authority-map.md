## Timing and coverage limits

Every `call` value is the duration of the named pytest function body. Rows 1–4 and 7–9 perform work before the final checker assertion, so none is an isolated subprocess cost. The `setup` rows are fixture setup phases. The two replay setup rows occur in separate CI matrix jobs, each selecting one lane and invoking `scripts/check.sh` ([workflow](../../../.github/workflows/ci.yml#L20), lines 71–74); module scope applies within each pytest process, not across jobs. The profile shows repeated setup for those lanes but does not identify each fixture's share.

The `rfl` branches recur in tests with distinct assertions: axiom acceptance, fresh replay, and ordered-plan completion. That establishes separate checks, not redundant coverage. The autouse isolation guard snapshots only `.doctor`, `deploy`, and `var` ([conftest.py](../../../tests/conftest.py#L40), lines 108–140); it does not establish the absence of fixture leaks elsewhere. The top ten include eight Linux container phases and two dev-arm phases, while lane totals and job setup also differ. These rows alone do not establish lane imbalance.

**No-Claim:** This map does not prove the absence of leaks or duplicate coverage, close the broad test audit, or replace the real authority tests. It does not infer speedup from test counts or fixture setup timing. No pytest node or Docker operation was run for this mapping.
