## Cache inventory and private restoration

`inventory()` walks every path below a cache project and records directory modes, file modes/sizes/SHA-256 digests, and symlink targets; it refuses broken/escaping links and special files ([helper](../../../tests/_linux_dependencies.py#L58)). `validate()` matches the recorded key inputs and full inventory, rechecks pinned project files, rejects package overrides, and verifies dependency packages ([helper](../../../tests/_linux_dependencies.py#L86)). `restore()` validates the source, copies it to the caller's destination, compares the destination's complete inventory with the expected inventory, and rechecks dependency packages ([helper](../../../tests/_linux_dependencies.py#L173)).

The mapped integration test supplies positive observables for the real private-project path: a fixed formal statement hash, nonempty Docker commands using network `none`, no cached-entry path passed into those commands, and unchanged source-cache inventory after mutating a private `.olean` ([test assertions](../../../tests/integration/test_container_statement_hash.py#L46)). Its patched `copytree` changes a copied `.olean`; the second restore must refuse with `dependency-cache-copy-mismatch`, and the source inventory must remain unchanged ([lines 64–76](../../../tests/integration/test_container_statement_hash.py#L64)). The `all(argv[0] == GIT ...)` assertion at line 50 is a negative property: an empty spy is compatible with “restore launched no non-Git/provisioning subprocess.” It is not, by itself, evidence of vacuity; the later hash and nonempty Docker assertions exercise the positive preparation path.

Unit tests use synthetic trees to prove that ignored `.olean` files, byte changes, extra/missing files, mode changes, link changes, directory changes, escaping links, special files, and incomplete/corrupt entries affect inventory or refuse restoration ([inventory cases](../../../tests/unit/test_linux_dependency_cache.py#L46), [invalid-entry cases](../../../tests/unit/test_linux_dependency_cache.py#L86)). The archive round-trip tests also verify exact image identity and restored dependency inventory, but patch `container.run_docker`, `container.image_id`, or `assert_pinned` through test helpers; they test helper control flow, not a real Docker image load ([test helpers](../../../tests/unit/test_linux_dependency_cache.py#L143), [round trip](../../../tests/unit/test_linux_dependency_cache.py#L187)). Those are different boundaries from the mapped real Linux restore and proof calls.

## Replay, refusal, and cleanup observables

The gold test compiles before clearing the spy, then requires exactly one `leanchecker --fresh` invocation for both `rfl` and `forged`; `rfl` must return `EXPECT_REPLAYED` with no reasons, while `forged` must return `KERNEL_REJECTED`, `rc:1`, and a replay diagnostic naming the declaration ([test](../../../tests/integration/test_container_statement_hash.py#L223)). It also asserts a nonempty set of Docker commands using the pinned image, disabled network, host user, and axiom-before-replay order ([lines 280–290](../../../tests/integration/test_container_statement_hash.py#L280)). The dev forged plan checks that the comparator is not run after the replay refusal ([test](../../../tests/integration/test_solution_build_compile.py#L491)).

The container runner requests `docker run --rm`; on timeout it issues `docker stop --time 0` and reports an unconfirmed-cleanup error if stopping fails ([container.py](../../../src/cairn/container.py#L182)). The timeout integration case asserts a stop command ([test line 527](../../../tests/integration/test_container_statement_hash.py#L527)). These are source-backed cleanup mechanisms and assertions, not proof from a run that the daemon contains no residual resources. Pytest-owned project/bundle roots use `tmp_path`/`tmp_path_factory`; the Linux bundle fixture additionally restores file permissions after `yield` ([fixture teardown](../../../tests/integration/test_container_statement_hash.py#L676)). Other module fixtures return their temporary paths without explicit teardown.

One untested cleanup observation is that `prepare()` has no explicit finalizer for its external `linux-mathlib-*` work directory or its `.partial-*` cache directory if validation or publication raises ([helper](../../../tests/_linux_dependencies.py#L128)). The work directory may be intentionally retained for diagnosis. This source audit records cleanup scope only; repository scratch retention follows the no-deletion invariant, and no removal is prescribed. No failure was induced. Archive export creates a separate staging directory and links published archive files from it ([helper](../../../tests/_linux_dependencies.py#L320)); the round-trip test explicitly expects that directory and matching inode links ([test](../../../tests/unit/test_linux_dependency_cache.py#L187)), so its persistence is part of that test's asserted behavior, not evidence of an accidental fixture leak.

## Cross-layer duplicates and planted negative

The mapped `rfl` cases recur at the axiom, fresh-replay, and ordered-plan boundaries. Their assertions differ: axiom acceptance and `sorryAx` refusal; actual fresh replay and forged-kernel refusal; and ordered-stage completion/blocking. The dev forged full plan and gold forged replay also exercise different arms and output contracts. No identical-shape unit duplicate is apparent among these mapped proof branches and the reviewed cache tests; this is not a suite-wide duplicate audit.

A cached replay verdict that bypassed process invocation would conflict with the required `leanchecker --fresh` command and result assertions in the `rfl` and `forged` branches; `replay == []` is expected only for `sorry`, which stops at axiom refusal ([assertions](../../../tests/integration/test_container_statement_hash.py#L254)). The `popen_spy` fixture appends argv before delegating through `super().__init__()` ([conftest.py](../../../tests/conftest.py#L143)); a replacement stub could still record argv, so command assertions alone do not prove the child process ran. The real-delegation guarantee comes from the fixture implementation. There is no separate process-identity assertion, and a stub that records expected argv and fabricates matching results could evade the result assertions if the fixture implementation were changed. No substitution or test was run.

**No-Claim:** This source-only audit does not prove global leak absence, global branch coverage, test-suite completeness, or speedup, and it does not authorize deleting tests. The profile timing is not an operation benchmark, and the source assertions cited here are not fresh execution evidence.
